# 原则修正：Guard 的 ROI 判据（2026-09-03）

## 起因

复盘 FS_NOT_OBSERVED（read-first）重复事件时，先后推导出两版原则：

1. 强版诱惑：「事实是唯一真元」「已确定的事实不得让模型再推理」「能事前判断就不该等第二次」——
   听起来自洽，甚至能形式化成 Guard(a, Fact_t) / Δ = Fact'−Fact。
2. 纠偏（本文件结论）：「**能确定地拒绝 ≠ 必须提前拒绝**」。

教训本身值得记录：漂亮的架构包装会诱惑我们为「理论上第二次也不该发生」去造 Fact Store /
增量投影 / Guard 规则 / 失效机制——**理论正确但工程上不值得**。直觉是方向信号，不是规格；
把直觉系统化成架构的那一步，是引入过度承诺风险最大的地方。

## 修正后的总原则（克制版）

> Runtime 只接管那些「**提前接管能显著降低错误成本**」的确定性；不是所有可以提前判断的
> 东西，都值得提前判断。

## Guard 值不值得存在的判据（三元组）

```
重复的真实成本（token / 步数 / 副作用）
× 错误信号的自明度（模型看到后能否自己改正）
× 前置条件检测的成本（会不会误判）
```

只有三者同时有利，guard 才值得做；否则让更便宜的层处理：

| 层 | 归属 |
|---|---|
| 工具自身语义约束（官方 enforcement） | 第一次执行自然拒绝——最便宜、最可靠 |
| Pre Guard | 仅在「重复已昂贵/危险/反复发生 + 前置条件便宜可测 + 信号不自明」时 |
| Circuit（事后二阶兜底） | 连「下一步该禁止什么」都无法由事实确定时 |

**架构谦逊原则**：Runtime 不要复制工具自己的边界。工具语义层已经是最可靠的事实生产器 +
执行边界；在它之上叠同义守卫是重复建设，除非有证据说官方层失效或成本失控。

## 案例结论：read-first 不需要新机制

- `edit(P) → FS_NOT_OBSERVED`：成本低（一次 tool call）、信号自明（错误信息直接说去 read）、
  检测需额外机制 → **官方 fail-closed 即最优**。
- 重复一次的代价健康且小；circuit 在阈值 2 开断并注入「别重试 edit」是合理兜底，不是缺陷。
- 「repeat-denial guard（第一次被拒后拦第二次）」候选：**降级**，仅当出现「同因重复真实成本
  失控」的证据再启用。
- 对照：pwsh 引号泥潭（B 臂 12 步）成本高但信号不自明、前置测不准 → 属 circuit/reminder 地盘。

## 关联

- 事前/事后两轴不是两套机制，是同一事实流的写端与读端；但「读端」的实现优先级服从上面的
  判据——纯投影（扫 log）先跑，事实物化视图只在性能/一致性证据出现后才考虑。
- 与既有纪律一致：宁缺毋滥、不造重框架、只在实证翻车点签合同。
